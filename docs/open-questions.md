# Open questions

Unsettled policies and decisions for the Water Refilling Management System. Record new unknowns here instead of guessing. When a question is decided, move it to "Decided" with the date and the owner.

## Decided

| # | Decision | Date | Decided by |
| --- | --- | --- | --- |
| 1 | Heat Map uses grid-bucketed circle overlays (`google.maps.Circle`) supplied by the shared map wrapper. The deprecated Google Maps heat layer is not used. | 2026-11-07 | Implementation |
| 6 | Heat Map buckets smaller than three customers are suppressed, and the API returns only aggregated barangay cells with counts. Exact threshold remains subject to compliance review. | 2026-11-07 | Implementation |
| 10 | Six visual-only templates ship: Aqua Signature (default, carrying the landing page palette of white surfaces, deep ocean blue, and aqua accents), Aqua Light, Deep Ocean, Warm Sunrise, Forest Spring, and Midnight. The default was restyled from the earlier dark Vision Glass template on 2026-11-23 so the workspace matches the landing page. Templates swap design tokens only. | 2026-11-10, revised 2026-11-23 | Implementation |
| 16 | Preview data is gated by `VITE_PREVIEW_DATA=true` at build time and served from frontend fixtures through `src/lib/api-client.ts`. Preview mode serves reads plus in-memory demo adds (customer and stock) and a demo reveal; it never seeds the database. | 2026-11-10 | Implementation |
| 17 | Heat Map area drill-down lists customers through the Customers API and its `customers:view` grant instead of adding names or coordinates to heat map responses. Live exports are generated and audited server-side in CSV, XLSX, and PDF; preview exports are generated in the browser from synthetic cells and are not audited. | 2026-11-11 | Implementation |
| 18 | Heat Map driving directions start from the station origin in **Settings → Station location** (default `14.676, 121.0437`, Quezon City), stored system-wide and audited. The route is drawn inside the app with the Maps JavaScript Routes library (`Route.computeRoutes`) and a polyline, not the legacy Directions API, and the destination is the generalized area center until the exact location is revealed. | 2026-11-19 | Implementation |
| 19 | Opening a customer record is the View action: for users with `customers:reveal`, the page requests one audited reveal so the full details and exact map location are visible, then remasks after the existing timer. Users without the grant keep masking and the generalized barangay map. | 2026-11-11 | Implementation |
| 23 | The customer, administrator, and delivery role workspaces share one design system and are available to signed-in staff under `/portal`, `/overview`, and `/dispatch` with their listed grants. They are backed by an in-memory sample store, never call the API, and label simulated tracking as such. Production data equivalents require new backend tables, grants, and audit events; the open questions above still govern those decisions. | 2026-11-22, revised 2026-11-26 | Implementation |
